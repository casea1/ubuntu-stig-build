GR - Ubuntu FIPS Mode Recovery

Audience: Grand Rapids DT.
Time: 20 minutes, plus one reboot. Console access required.

Use this when a machine has lost FIPS mode, or boots the FIPS kernel and then fails. Both faults are caused by apt autoremove removing FIPS packages.

Symptoms

What you seeFault
/proc/sys/crypto/fips_enabled missing, or reads 0Either
uname -r does not end in -fipsEither
At boot: not a valid LUKS device, No used slots detected, and every passphrase rejectedA
At boot: a missing bootdev argument, then the machine returns to the normal kernelB

A machine can have both. Fixing one and not the other looks the same as fixing neither.

The passphrase rejection in fault A is not a wrong passphrase. The machine cannot read the encrypted disk at all, so it never reaches the point of checking one. Do not reset the passphrase.

Before You Start

  • Console access (monitor and keyboard). Do not attempt this remotely. If the machine does not come up you must be able to pick a menu entry.
  • The LUKS passphrase for the machine.
  • For fault A, the file openssl-fips-module-3_*.deb, collected from a machine that is working. Step 3 covers this.

End of the Introduction field. Everything below goes in Instructions.

1. Confirm the Fault

Run on the affected machine:

sudo it-fips

Read the two lines below. They identify which fault you have.

Line in the outputMeaningGo to
no OpenSSL FIPS provider installed on this boxFault AStep 3
nothing sets bootdev=Fault BStep 4
Both linesBoth faultsStep 3, then 4
Neither, and everything reads OKNo fault foundStep 5

2. Confirm Against a Working Machine

Run this on the affected machine and on one that boots FIPS correctly, and compare:

cat /proc/cmdline | tr ' ' '\n' | grep -E 'fips|bootdev'
dpkg -l | awk '/fips/ {print $2, $3}'

A working machine shows fips=1 and bootdev=/dev/disk/by-uuid/..., and lists openssl-fips-module-3. Anything the affected machine is missing is what you are restoring.

3. Fault A: Restore the OpenSSL FIPS Provider

On a machine that is working and has network access, collect the file. This installs nothing and restarts nothing:

mkdir -p ~/fips-debs && cd ~/fips-debs
sudo apt-get download openssl-fips-module-3
sudo chown "$USER":"$USER" ./*.deb
ls -l

Do not run pro enable fips-updates on a machine to collect these files. It cannot be enabled for downloads only and will convert that machine to FIPS.

Copy the file to the affected machine, then:

sudo apt-get install ./openssl-fips-module-3_*.deb
ls -l /usr/lib/x86_64-linux-gnu/ossl-modules/fips.so

The second command must list a file. If it does not, stop and escalate.

4. Fault B: Restore the Boot Parameter

sudo it-fips fix

This writes both fips=1 and bootdev=, marks the FIPS packages so they cannot be removed automatically, and rebuilds the boot configuration. It changes nothing about which kernel the machine boots.

Confirm it worked:

sudo it-fips

Every line should now read OK except the first section, which will still report that the machine is not running the FIPS kernel. That is expected until step 5.

5. Switch to the FIPS Kernel

sudo it-fips boot
sudo reboot

Stay at the console for this reboot. The machine is set to try the FIPS kernel once, but it will not fall back on its own. If it does not come up, power cycle it and select the entry without -fips in the name from the boot menu, then escalate.

If the machine stops at a passphrase prompt, enter the LUKS passphrase. This is normal on the first FIPS boot after a repair.

6. Make It Permanent

Once the machine is back up:

sudo it-fips confirm
sudo it-fips

confirm sets the FIPS kernel as the default. Until it runs, the machine is only running FIPS for this one boot.

7. Verify

uname -r
cat /proc/sys/crypto/fips_enabled
CommandRequired output
uname -rEnds in -fips
cat /proc/sys/crypto/fips_enabled1
sudo it-fipsEvery line OK

Reboot once more without touching anything and confirm the machine returns to FIPS on its own. That is the test that it is fixed rather than temporarily working.

8. Prevent It Happening Again

Never run sudo apt autoremove on these machines. That command is the cause of this fault.

it-fips fix in step 4 already marked the packages as protected. Confirm it:

apt-config dump APT::NeverAutoRemove | grep -i fips

This must list several entries. If it lists nothing, run sudo it-pull and check again.
